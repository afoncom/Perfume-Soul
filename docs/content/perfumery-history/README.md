# История дня Perfume Soul

## Согласованный формат

Период: **01.12.2026–30.11.2028 включительно, 731 публикация**.

День и месяц исторического события совпадают с днём и месяцем публикации. Год — исторический. На каждое повторяющееся число календаря нужны два разных события; на 29 февраля — одно. Пересказ одного события другими словами не считается новым событием.

Одна история содержит заголовок и **только полный текст**, без `shortStory`. Время чтения — около 1,5–2 минут. Редакционный ориентир: 270–330 русских слов или 300–360 английских; оценка при 180 и 200 словах в минуту соответственно. Верхние границы при этих скоростях — 360 и 400 слов. Скорость конкретного читателя может отличаться. Не растягивать материал, если подтверждённых фактов недостаточно.

Разрешены история аромата, бренд, парфюмер, ингредиент, культурный факт и техника создания. Даты рождения и другие события жизни людей подходят, если рассказ посвящён их вкладу в парфюмерию. Категории не заполняются искусственно ради равных пропорций.

## Допуск событий

Основной порядок: в `events.json` входят **события с проверенной точной датой**. Источник должен явно подтверждать день, месяц, год и именно названное событие. Поисковый фрагмент, дата статьи, предполагаемая дата, спорный календарь и план будущего запуска не дают допуска.

Предпочтительны документы дома, музея, профессиональной организации, архив или свидетельство участника. Наличие красивого сюжета не заменяет доказательство даты. Для патента различать подачу, публикацию и выдачу; для выставки — вернисаж и публичное открытие; для аромата — презентацию, начало продаж и регион запуска.

`verified` означает проверку **даты и узко сформулированного события**, а не готовность всех подробностей будущей истории. `storyAngleRu` — направление дальнейшей работы, не набор уже доказанных исторических утверждений. Перед написанием нужен отдельный факт-пакет со ссылками на каждое существенное утверждение.

Исключение, согласованное пользователем: пакеты `perfume_soul_stories_compact_001.json` и `perfume_soul_stories_compact_cumulative_197.json` перенесены по предоставленным датам и ссылкам без независимой проверки. Новые события имеют статус `user_provided`, факт-пакеты — `user_provided_fact_packet`. Для 30 непрочитанных ссылок первого пакета указан статус `not_opened_user_provided`, для 302 ссылок накопительного пакета — `not_independently_opened`. 15.11.2026 добавлен пакет `perfume_soul_new_coverage_draft.json`: 248 историй со статусом `user_provided` и 433 новых ссылок со статусом `not_independently_opened`. Короткие тексты пакетов сохранены по согласованию пользователя; общий ориентир длины выше остаётся прежним.

## Файлы и текущий результат

- `events.json` — реестр исследования: **731 событие: 294 проверенных и 437 предоставленных пользователем; 1779 записей источников**. Новые ссылки не объявлены прочитанными; записи источников не равнозначны независимым публикациям.
- `coverage.csv` — все **366** комбинаций дня и месяца: требуемое число событий, проверенные события, сохранённые истории и остаток. `missing_events` считается по сохранённым историям; `saved_stories` и `user_provided_events` отделяют наполнение от проверки, а ID непроверенных событий находятся в `user_provided_event_ids`. `unfilled` означает пробел в текущем исследовании, а не доказанное отсутствие события в истории.
- `generation-prompt.md` — reusable prompt для одного полного RU/EN рассказа по проверенному факт-пакету.
- `research-notes.md` — найденные риски источников и направления продолжения исследования.
- `fact-packets.json` — 731 факт-пакет: 294 проверенных и 437 по предоставленным материалам.
- `stories.draft.json` — 731 рассказ RU/EN со статусом `draft`, без отдельного краткого текста; компактная длина новых пакетов согласована пользователем.

Покрытие по сохранённым историям: закрыты все 366 сочетаний дня и месяца, частично заполненных и пустых нет. ## Связь с backend

Исследовательские материалы находятся в `docs/content`. Скрипт `backend/PerfumeSoulBackend/scripts/generate_perfumery_history_resource.py` создаёт из `stories.draft.json` компактный двуязычный ресурс в `backend/PerfumeSoulBackend/Sources/PerfumeSoulBackend/Requests/perfumery-history/Resources`. Миграция автоматически сохраняет его 731 записей в таблицу `perfumery_history_entries` при первом запуске backend с этой версией. Для последующих изменений текстов в уже мигрированной базе потребуется отдельная миграция данных.

Редакционный формат описан в prompt: `publicationDate`, `eventId`, `eventDate`, `category`, `localizations.ru/en.title`, `localizations.ru/en.fullStory`, `sourceIds`. `shortStory` отсутствует. Рабочий API отдаёт выбранные по `Accept-Language` `title` и `fullStory` вместе с `publicationDate` и `eventYear`.

Backend выбирает историю по текущей календарной дате в часовом поясе, переданном iOS в `timeZone`; при его отсутствии используется UTC. До начала периода, после его конца или при отсутствии записи API возвращает 404. Экран истории обновляется при смене дня и после возвращения приложения из фона.

## Необходимая проверка данных

Проверять валидность JSON, реальные календарные даты, уникальность событий и групп, ссылки на существующие источники и честный подсчёт покрытия. В готовом каталоге дополнительно проверять все 731 публикации, совпадение исторических дня/месяца с публикацией, отсутствие повторных событий и рассказов, обе локализации и длину текста.

Билды приложения и общие тестовые прогоны для исследования контента не требуются.
